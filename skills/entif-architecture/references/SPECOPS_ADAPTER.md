# SpecOps adapter boundary

SpecOps is the desired-state and temporal-motion substrate. Entif Architecture routes/composes it; it does not fork it.

Prefer canonical capabilities for desired-state specs/principles, spec impact, temporal plan DAGs, depends/awaits/specs/issues/pr relations, readiness/next-work inspection, drift audit, validation/freeze/closeout, and progressive spec context.

When Codex/runtime repeatedly uses SpecOps or another sizable API surface, prefer the relevant AXI. If canonical interfaces are unavailable, classify/handoff without inventing fake authority.
